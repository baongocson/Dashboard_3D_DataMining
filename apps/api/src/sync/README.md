# B033 local-dev sync foundation

createApp defaults to no sync routes; explicit localSync injection now registers the local-only HTTP foundation described below. contracts.ts remains pure shape/policy preparation. service.ts now uses actual auth/Mongo/private-byte storage for local-dev batch declaration tests, authorized by the owner decision to split the B033 prerequisite by verified B032 capability. Full B033 remains unaccepted; B032 stays partial and physical cleanup remains unverified under the no-delete decision.

prepareDeclaration validates the existing S11 shape and C20 batch/group/body bounds. It requires unique IDs and complete/disjoint atomic membership, reconstructs each typed mutation's ordered descriptor list independently of the global artifact order, and checks the unchanged C02 canonical business hash. Only the five typed metadata/version kinds currently owned by B031 can be prepared; no arbitrary upsert or unavailable kind is accepted.

Version descriptor order is manifest, ordered leaf table chunks, then optional lineage. Imported dataset source comes first, matching B031. Actual file hashes/table/lineage/source rows, serverGeneration, owner/ref/session/tombstone checks remain runtime responsibilities. A correct declared hash is not proof that bytes or server commits exist.

The pure dependency pass rejects self/mutation cycles, cross-project internal dependencies and cycles introduced by collapsing an otherwise acyclic mutation graph into atomic groups. It returns topological group/member order. Unknown external mutation IDs remain explicitly unresolved for authoritative lookup; they are never assumed committed or assigned a guessed server revision.

Returned declaration and descriptor snapshots are cloned and frozen. batchSnapshotHash identifies the declaration, separate from each mutation's business hash. Batch transport identity is not inserted into or rewritten inside mutation payload hashes.

Implementation-plan§1 permits this independent preparation while another capability is blocked. The later explicit owner decision permits local-dev service work using verified B032 capabilities; it does not mark B032 physical cleanup passed or open product HTTP. Full B033 still requires actual receipt/idempotency/group transactions, upload planning, conflict preservation, partial ACK, auth/generation/tombstone fences and reconciliation/expiry evidence.

assembleAck is also pure preparation. Its inputs must eventually come from authoritative runtime outcomes under real server fences, never client claims. It validates the current declaration and generation, requires an exact result for every snapshot member, rejects half-ACKed groups, checks hash/artifact/entity/conflict/revision shape and projects only public S11 fields. Internal branchResult/storage fields are dropped. Node tests compare its synthetic outputs with the existing client validator; this is contract compatibility evidence, not server commit/receipt proof or pointer/ref rebinding.

prepareCommitRequest uses the new primary sync-commit-request.json. The body has only serverGeneration and unique mutationIds (1..100). Batch identity comes from the route context; payload/artifact/atomic-group/receipt/owner overrides are rejected. The declaration argument must eventually come from the server's owner-scoped immutable batch store, not from client commit-body data.

Commit selection requires IDs already in that declaration and full membership of every selected atomic group. Whole-group subsets are permitted without silently adding omitted mutations. The immutable returned order follows dependencies. Dependencies omitted from the request or outside the batch become explicit requiredReceipts, scoped by project+mutation ID; expectedPayloadHash is provided when the dependency was declared, otherwise null. They remain unresolved until authoritative receipt/fence checks; no revision is guessed and no commit or ACK is implied.

Request, route context, ACK outcomes and ACK options are captured before the first asynchronous hash step. Caller edits during the await cannot rewrite a validated snapshot. These copied context values are not live permission/generation fences: runtime must recheck actual owner/session/generation/tombstone/ref state in the authoritative transaction and at the appropriate response boundary.

assembleDeclarationPlan projects future authoritative artifact findings into sync-declaration-plan.json. Every declared artifact has exactly one disposition: needsUpload, alreadyPresent or rejected. Optional mutation rejections name known IDs. Public upload views must have unique upload IDs, matching generation and valid chunk index/offset/length metadata. Present artifacts must match declared hash and size; verified staging remains distinct from ready. A verifying upload is pending verification, not permission for automatic resend or retry.

The response is captured before async hashing, cloned/frozen, and capped at1MiB without truncation. Findings here are synthetic DTO inputs. No clock/expiry, bytes, owner, session, generation, lease, ref or receipt lookup occurs. Future runtime must obtain fresh authoritative findings and enforce all live fences; a declaration plan never ACKs metadata commit.

prepareReceiptReplay is a pure internal policy over hypothetical authoritative receipt/identity observations. Context captures owner ID, requested declared mutation ID, current generation and an explicit serverNow epoch-millisecond value. Record committedAt/expiresAt are epoch milliseconds; future runtime must normalize DB dates and use its own trusted clock, never client timestamps. Logical replay retention must be at least90days. No record is deleted or TTL policy changed.

Both missing yields unresolved/noCommitProof, which is not permission to create a mutation. Missing/expired receipt or missing durable identity requires reconciliation. Matching owner/project/mutation/hash/entity/generation and public result equivalence are required to project one replay receipt. Stable conflict IDs and artifact IDs come from the supplied retained result; nothing is regenerated. A replayPrepared result is not a batch or atomic-group ACK. Runtime must resolve every group member and enforce live auth/session/generation/tombstone/ref/lineage and commit fences before replying. Those pure-policy tests alone do not establish authoritative lookup or commit proof; actual runtime receipt and reconciliation evidence is described below.

SyncService currently persists immutable owner-scoped declarations (unique ownerId+batchId), rejects a changed snapshot before upload work, and plans actual storage uploads. A logical30minute batch expiry never deletes the record or permits reusing mutation IDs as new. Repeated declaration preserves the original expiry. read returns a detached persisted declaration, not an ACK. Metadata-only project.create can be declared before project creation; artifact upload requires the actual project to exist.

Planning reads and hashes real verified/ready bytes outside Mongo transactions, then rechecks owner/session/generation/project/tombstone and artifact revision/key/state under actual fences before projecting alreadyPresent. Ready additionally requires a real hard artifact ref. Resume views come from actual chunk records. A concurrent complete/cancel/session replacement may fail closed and require an explicit user retry; no automatic retry loop is added. The declaration paths do not commit entities/refs/receipts. The commit path now composes actual MetadataService and StorageService authority in a separate whole-group transaction. The declaration-only attachment case still uses existing MetadataService directly; atomic commit cases exercise SyncService itself.

The first runtime harness attempt hit sandbox loopback EACCES before any cases; its evidence and namespace are retained. The authorized unsandboxed owned-loopback run tests real Mongo/private bytes. Missing-byte coverage changes only a new fixture metadata pointer to a nonexistent key; all actual files remain. Race coverage injects logout/generation/tombstone changes after an actual byte hash. Service/connection reopen is not a Node/Mongo process restart, power-loss or real cleanup proof.

commit accepts the primary ID-only request and immutable persisted batch. Hash/format/full-byte proof preparation occurs outside transactions. Each whole group uses actual auth/session, generation, project/tombstone and artifact authority fences; metadata/refs/readiness/durable identity, replay receipt, monotonic per-project change sequence and completed-group status commit together. Aborted groups roll back every write; previously committed independent groups remain. No transaction spans all batch history.

Actual replay lookup requires a matching retained durable identity and90day logical replay receipt with equivalent public results, owner/project/hash/entity/current generation. No TTL or deletion is introduced. A B031 commit identity alone does not manufacture a B033 replay receipt. Missing/expired authority requires reconciliation and never unconditional reinsert. New transport IDs keep mutation identity; replay adds no revision/change/conflict ID.

Omitted whole groups return MUTATION_NOT_REQUESTED, and declared but uncommitted dependencies return DEPENDENCY_NOT_READY. Unknown external dependency proof requires reconciliation. Groups missing verified bytes remain pending; independent groups can ACK. The response partition covers the original snapshot and is checked against the client validator. No retry loop is added. Project/dataset rename REVISION_CONFLICT remains pending without an invented copy. Version conflicts preserve actual branches; local reconciliation/page/cursor/HTTP capabilities are described below, while client integration remains incomplete. Final response fences can withhold an ACK after a real group commit (for example, logout); receipt remains for owner reauth and explicit replay. This keeps server committed distinct from client synced.

Chained version groups with row lineage now pass earlier same-project opaque MetadataService prepared handles to storage preparation. Storage accepts only its own private WeakMap attachment proofs bound to owner/project/generation and a cloned verified version snapshot. If that source version is not yet in DB, source-row checks read/hash its actual retained manifest/chunk bytes from the proof, still outside transactions. No client-supplied source rows/version objects are trusted. Handles are bounded20 and captured before await. The actual group transaction must subsequently commit/resolve the real source version and recheck artifact revisions/readiness; a preflight handle alone cannot publish a version or bypass dependencies.

C08 project ordering is deliberate: intent and upload require an actual committed project. A project declaration alone publishes nothing. Commit project first, then START a real intent and upload/commit the imported dataset. No upload implicitly creates a project, no import starts before its server intent, and declaration is never called server commit.

SyncService opts into MetadataService.preserveVersionConflicts; B031 default remainsfalse. A moved version head preserves the current head and forks a real syncConflict branch at the client parent after checking source/parent/fork/tombstones and proving the stale known guard from retained branch-result history. Null/0 is not authority to treat a populated branch empty. Unknown history requires reconciliation. Version/mutation IDs, the original stored content and canonical hash stay unchanged; the immutable row records actual branch placement separately. Metadata reads expose actual branchId and optional declaredBranchId for that distinction.

The actual conflict branch/ref/readiness/durable identity, M19 conflict references, replay receipt, change and group state commit together. Public ACK contains conflictRefs, never private branchResult. Replay reuses the exact branch; no default branch/local pointer/dashboard binding is switched. A dependency receipt privately binds declaredBranchId to the actual branch, so subsequent offline steps continue there without rewriting business payload/hash. If that actual branch itself moved, a secondary fork preserves it too. Known new commands may address an existing server syncConflict branch with its exact descriptor; server refuses creating one from a client-supplied syncConflict descriptor.

Final replay/ACK checks include returned entity/artifact/conflict IDs, dataset and declared branch tombstones, plus actual dataset/branch ownership. A target deleted after commit can withhold final ACK while retaining the committed receipt; retry never creates replacement IDs. Other typed-resource copy kinds remain unavailable until their owning resource foundation; full B033 reconciliation/changefeed/localHTTP still needs evidence.

ReconciliationService currently covers submitted summaries only: known entity/artifact comparisons and pending mutation groups. completeServerManifest=false, coverage=submittedSummaries, requiresUserReview=true and mutationsApplied=false are strict response constants. It neither executes mutations nor clears client reconciliationRequired/syncGate; a reconciliation page is not a sync-ack DTO. Full project manifest/changefeed/client integration and local HTTP remain unfinished.

Requests are strict/captured before await and capped at1MiB,100project scopes,1000known entities/artifacts each,100pending and20members/group. These are request metadata caps, not history/business count limits. Actual fenced snapshot reads compare owner-scoped metadata and retained commit identity, immutable version hash/source refs/revisions and ready artifact references; expired/missing replay receipt does not authorize a fresh insert. Artifact files are actually read/hash-checked outside transactions, then identity/entities/refs/revisions/keys/generation are rechecked before sealing. Missing/mismatched proof stays held, owner tombstones yield blockedDeleted, and no half-group ACK proposal is made.

The submitted-row plan is retained as immutable rows with SHA256 binding: canonicalJSON({id:reconciliationId,requestHash,serverGeneration,createdAt,manifestBindings})+newline followed by canonicalJSON(row)+newline for every ordered row. Each page binds that hash/requestHash/owner/generation, offset/count, fixed page maximum100 and1MiB response budget with continuation. Opaque cursor records are owner/plan/generation-bound,30min logical expiry, no TTL/deletion. Before returning ACK proposals, every member of their group is revalidated, including members on another page. Session/gen/deletion/proof change fails closed with requiresNewSnapshot. Ordinary concurrent metadata updates do not rewrite the captured comparison rows.

Only auth/control fences and reconciliation header/row/cursor metadata are written. Entity/ref/identity/receipt/change/upload/artifact metadata and byte files remain unchanged by comparison. Byte proof is at snapshot creation, not a continuous disk-availability guarantee. Failed/building/expired namespaces are retained; one live building snapshot per owner is allowed, and a stale build expires logically without deletion. No implicit retry, new resource IDs, server entity conflict copies or client ACK application occur in this phase.

ManifestService now materializes full project metadata for the explicit registered foundation kinds in resourceKinds: project/dataset/version/branch/artifact/reference/conflict/tombstone. completeServerManifest=true covers that registry, not future unimplemented resource kinds. Each new resource kind must extend the registry/schema before product enablement. bytesVerified=false and referenceClosureVerified=false are strict constants: a metadata artifact state is not current byte integrity, graph closure or offline readiness. There is no byte download/cache/gate/client ACK or product route registration in this stage.

An actual Mongo snapshot read session (snapshot:true, causalConsistency:false) pins one point across collections outside a long transaction. Public snapshotEnabled/inTransaction API and actual command readConcern/atClusterTime are tested; no internal snapshotTime property is used. Cursors fetch16documents at a time; materialized public-row buffers stay at most100rows/1MiB and are written separately with live owner/session/generation/project-deletion fences. These buffer measurements are not peak RAM evidence. History has no1000-version cap: the probe commits1006real versions through bounded mutation batches/groups and enumerates all4030metadata rows.

The public checksum is SHA256 over canonicalJSON({manifestId,projectId,serverGeneration,requestHash,createdAt,sequence,metadataRevision,resourceKinds})+newline and every ordered canonicalJSON(row)+newline. All pages bind this hash and the actual snapshot sequence anchor, owner/project/generation, offset/count and opaque cursor. Thirty-minute logical expiry never deletes rows. Ordinary concurrent rename/version commits keep one old point; generation/session/deletion/expiry/history-loss/corrupt metadata fail closed with requiresNewSnapshot. Unknown legacy tombstone scope fails rather than silently dropping deletion information. Failed materializations retain partial rows and stay unreadable; only one live build per owner is allowed.

The sequence and private metadataRevision anchor now support the registered-Sync changefeed described below. B080 offline prepare/resume/readiness and HTTP/client integration remain unopened.

ChangefeedService is unregistered local-dev service code. open accepts only an actual owned ready manifest ID and generation/page-size options, never a caller sequence. The manifest must still be within its30minute logical window and include metadataRevision. Old-format manifests require a fresh snapshot. The private marker increments once per fresh MetadataService mutation in the same transaction; replay does not increment it. Sync journals record the matching marker and identities record their kind. This marker is separate from business revision, expectedHead and payloadHash.

Opaque owner/project/generation-bound checkpoints expire logically after90days. A first read freezes an upper sequence/metadataRevision and range hash; repeated reads remain stable while new journaled writes wait for an explicit resume poll. Page/range cursors retain the source checkpoint expiry, not the manifest30minute window. Completed ranges alone expose the resume checkpoint. Pages are bounded100events/1MiB and validate contiguous sequence, event age within90days, marker progression, actual durable identity and matching retained receipt/result before projecting public events. No timestamp filtering silently skips old events.

A direct legacy MetadataService write after the anchor advances the marker without a Sync event. Delta divergence fails closed with410/requiresReconciliation instead of inventing a legacy event or losing a write; a fresh full manifest absorbs the earlier state. Journal gaps, mismatched proof, expired cursor/event horizon, changed generation and deleted targets also hold the feed. This is registered-Sync coverage with explicit detection of unjournaled legacy writes, not a full legacy event journal. Counter overflow rolls back the whole mutation transaction.

Manifest and range SHA256 headers include metadataRevision bindings. Read paths write only control/fence and feed checkpoint/range/cursor records, never domain entities or bytes. There is no TTL/physical removal, automatic retry, S11 ACK, outbox application or sync-gate transition. acknowledgesOutbox=false/mutationsApplied=false are strict public constants; full reconciliation/HTTP/client integration remains incomplete.
