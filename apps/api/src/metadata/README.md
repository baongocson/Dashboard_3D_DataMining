# B031 metadata foundation (local-dev only)

`MetadataService` shares the B030 `AuthService` and its Mongo transaction/session fence. `createApp(auth,{metadata})` registers eight O03/O04 routes; no listener/public auth is started. The default app stays auth-only. Project POST passes a typed mutation into `commit`, never a parallel CRUD path. Other metadata mutations are internal foundation handlers for B033, not a second sync API.

Private DTOs and request schemas live in `packages/contracts/schemas/metadata-*.json`, with generated validators and `openapi/metadata.local.v1.json`. Read lists use opaque persisted owner/kind/scope-bound cursors, 30min expiry and max100 returned items. These are live keyset pages ordered by stable ID, not consistent project snapshot manifests (B080). Version metadata includes its exact immutable source refs/config/manifest, revision and content commitment; it never implies server recomputed metrics or join output.

Commit checks owner/session/generation, ancestor tombstones, project dependency fence, hash/typed payload, existing dependencies and immutable identity in one Mongo transaction. `prepareMutation` hashes outside the transaction and returns an opaque handle whose immutable content stays in a private WeakMap. B033 can call `commitPrepared` for several handles inside one shared `auth.withFence` transaction; a later failure then rolls every group member back. The ordinary `commit` wraps exactly these same methods. Project/dataset rename updates name/revision only. Version create uses baseRevision0 plus known server head or dependency identity, per ADR A. The resulting branch/version/revision tuple is internal `branchResult`; B033 must translate the public S11 receipt without this internal field. Stale head rejects here; B033 owns stable conflict branch preservation. No current pointer/reopen state is changed by version reads or ACK. `dataset.head.select` remains unavailable until its owning command flow; no branch head rewrite is used to simulate undo.

New version IDs can only reference already committed sources in this owner/project, preventing cycles; parents/forks must belong to the same dataset. Continuing from an older version requires a new undoContinuation branch. Initial branch/V0 must match the new dataset declaration, preventing a second initial V0 on an existing dataset. Source/parent/artifact hard references are stored with the version and commit identity. Artifact readiness failure rolls the complete transaction back.

Import intent binds owner/project/session/epoch, logical import/mutation/dataset/V0 IDs, source revisions and config hash. TTL30min is checked in code; no intent TTL deletion loses old identity. Renewal checks durable commit identity before granting work and retains the opaque intent ID, so the mutation business hash need not change. New auth must renew an old uncommitted intent before it can commit. The canonical config hash is SHA-256 of `{parseConfig,operationSnapshot}`; B041 must use the same confirmed snapshot. Expired intent returns PREVIEW_STALE409 (existing catalog), not a new unregistered error. Config/IDs cannot be changed under an old logical import ID.

`ArtifactAuthority.assertReady` is trusted server code and may only check/attach previously verified artifact metadata inside the current Mongo transaction. It must not upload, read files, hash large bytes, call network or perform computation in the transaction. B032 must verify exact bytes/format/graph outside it and participate in the reference/session/project fence at attachment. With no authority installed, dataset/version commits fail ARTIFACT_NOT_READY and publish nothing. The B031 harness injects an explicitly synthetic fixture metadata authority; that is not evidence for actual artifact storage, byte verification, parser or numerical correctness.

Durable commit identities have no TTL here and are separate from future bounded replay receipts. B033 owns expiry/receipt/partial ACK/conflict/reconciliation policies and atomic groups. B034 owns resource/run DTOs beyond dataset/version; B041/B043 own import/undo/current-pointer UI. No production entry, data deletion, adapter, cloud/mail/AI or deploy is enabled.
